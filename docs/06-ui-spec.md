# 06 UI 规格

## 1. 总体风格

参考：`docs/assets/ui-reference.png`

关键词：
- 简洁
- 白底/浅色
- 清晰层级
- 蓝色作为主要强调色
- Material 3
- 手机单手操作优先
- 桌面宽屏下不把内容无限拉宽

移动端使用底部导航栏承载四个主页面。

Windows Desktop 使用响应式宽屏布局，优先参考原始截图的桌面视觉：应用标题 + 四个主入口可采用顶部导航；也允许使用 NavigationRail，但必须保持四个功能入口名称和信息结构不变。表单和统计内容应设置合理最大宽度并居中/分栏，避免 1920px 宽屏下表单横跨整个窗口。

## 2. 记一笔

目标：尽量少操作完成一笔支出。

页面元素：

```text
金额
[ ¥ 18.5 ]

一级分类
[餐饮] [交通] [生活] ...

二级分类
[早餐] [午餐] [晚餐] ...

消费时间
[2026-08-14 15:08]

[保存]
```

规则：
- 时间默认现在
- 一级分类只显示 active
- 二级分类只显示 active 且父级 active
- 选择一级分类后只展示其子分类
- 金额键盘使用数字/小数输入
- 最多 1 位小数
- 保存成功给轻量反馈并清空金额

## 3. 支出列表

顶部：
- 当前查询范围
- 默认当前生活费周期
- 可切换上一期/下一期
- 可进入自定义日期范围

列表按 `spent_at DESC`。

建议按日期分组：

```text
8月28日
12:30   餐饮 > 午餐       ¥18
08:10   餐饮 > 早餐        ¥8.5

8月27日
19:20   娱乐 > 游戏        ¥30
```

点击一条记录进入编辑。

编辑页/弹层：
- 金额
- 一级分类
- 二级分类
- 时间
- 保存修改
- 删除

删除必须二次确认。

## 4. 分类管理

一级分类使用可展开列表。

```text
餐饮                    [编辑]
  早餐                  [编辑]
  午餐                  [编辑]
  晚餐                  [编辑]

[+ 新增一级分类]
```

功能：
- 新增一级分类
- 新增二级分类
- 改名
- 停用
- 恢复
- 修改二级分类所属一级分类

建议提供“已停用分类”入口，方便恢复。

MVP 不做拖拽排序。

## 5. 概述统计

### 完整生活费周期

顶部周期选择：

```text
< 2026 年 8 月 >
08/25 - 09/24
```

预算卡片：

```text
本期预算   ¥2500
已消费     ¥1860
剩余       ¥640
使用率     74%
```

超支时改成：

```text
已超支 ¥135
```

下方：

1. 一级分类环形图
2. 一级分类金额列表
3. 点击/展开一级分类后显示二级分类汇总
4. 每日消费趋势图

### 自定义日期范围

顶部明确标识“自定义范围”。

显示：
- 总支出
- 环形图
- 一级/二级分类统计
- 每日消费趋势

不显示任何预算卡片和预算进度。

## 6. 设置页

不是主导航 Tab。

入口可放在概述统计 AppBar 右上角。

MVP 设置：
- 默认月预算
- 初始生活费周期起始日（当前 25）
- CSV 导出

## 7. Windows Desktop 验收布局

Windows 端不是单纯把手机页面放大。至少满足：
- 窗口可调整大小，不发生明显 overflow。
- 四个主入口在常见桌面宽度下清晰可见。
- “记一笔”表单保持合适阅读宽度。
- “支出列表”可以利用更宽空间展示时间、分类、金额。
- “概述统计”在宽屏下允许卡片/图表做合理并排，但窄窗口时仍可纵向排列。
- 分类管理在桌面端可用更宽的树状/分组列表，但业务行为与移动端完全一致。

## 8. 空状态

必须设计：
- 没有支出记录
- 自定义范围没有数据
- 分类为空/停用完
- 当前周期尚无消费

空状态不要报错，应给出明确下一步操作。
