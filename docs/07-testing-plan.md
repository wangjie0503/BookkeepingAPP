# 07 测试计划

## 1. 核心原则

这个项目数据量小，但业务边界很多。测试重点不是性能，而是：

- 金额精度
- 分类历史行为
- 周期边界
- 统计一致性
- UI 写入后立即刷新

## 2. 单元测试

### 金额

必须覆盖：
- `18 -> 180 角`
- `18.5 -> 185 角`
- 0 拒绝
- 负数拒绝
- 两位小数拒绝
- 非数字拒绝

### 分类

必须覆盖：
- 全局重名拒绝
- 停用分类仍占用名称
- 一级分类停用不修改子分类 active 状态
- 父级停用时子分类不可用于新增支出
- 恢复父级后子分类回到原状态
- 二级分类移动后历史统计归到新父级
- 分类改名后历史显示新名称

### 周期

以每月 25 日为例覆盖：
- 8/25 属于 8 月周期
- 9/24 属于 8 月周期
- 9/25 属于 9 月周期
- 新周期预算复制默认预算
- 修改默认预算不影响历史周期
- 修改某期预算只影响该期

### 统计

使用固定测试数据验证：
- 总金额
- 一级分类聚合
- 二级分类聚合
- 每日聚合
- 自定义日期范围边界包含关系

## 3. 数据库测试

至少验证：
- SQLite 重启后数据存在
- FK 关系正确
- 分类停用不删除历史支出
- 删除支出后统计同步变化
- schema migration 可执行

## 4. Widget / 页面测试

至少覆盖核心链路：

### 记一笔
- 选择分类
- 输入金额
- 默认时间
- 保存成功
- 列表出现新记录

### 编辑删除
- 修改金额
- 修改分类
- 修改时间
- 删除前弹确认
- 删除后列表和统计变化

### 分类管理
- 新增分类后记一笔页面立即出现
- 停用后立即消失
- 恢复后重新出现

### 概述统计
- 有数据时显示正确汇总
- 无数据时空状态正常
- 自定义范围不显示预算

## 5. 快速桌面验收

开发阶段优先在 Windows Desktop 上做高频 smoke test。每个里程碑完成后至少执行一次：

```text
flutter devices
flutter run -d windows
```

在 Windows App 中验证当前里程碑的真实 UI、SQLite 持久化、状态刷新和图表，不允许只看 Widget Test 就认为功能可用。

Windows 端重点检查：
- 窗口调整大小无 overflow
- 导航正常
- 记账写入后列表/统计立即刷新
- 关闭程序重新打开后 SQLite 数据仍存在
- CSV 可以导出到本机可访问位置

## 6. Android 手工验收

最终 Android 包至少手工跑一遍：

1. 首次安装
2. 默认分类存在
3. 设置默认预算
4. 连续记 5~10 笔不同分类支出
5. 修改一笔
6. 删除一笔
7. 停用一个二级分类
8. 移动一个二级分类
9. 查看概述统计
10. 查看自定义日期范围
11. 导出 CSV
12. 杀掉 App 重启，确认数据仍存在

## 7. 完成前命令

Codex 应运行当前 Flutter 工程对应的：
- format
- analyze
- test
- Windows run/smoke test
- Windows release build
- Android build

如果任何一项失败，不得声称项目完成。

具体命令和验收节奏见 `docs/10-desktop-validation.md`。
