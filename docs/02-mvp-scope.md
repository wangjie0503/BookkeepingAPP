# 02 MVP 范围

## 必须完成

### 基础
- Flutter 工程可运行
- Windows Desktop 可直接运行并完成核心功能验收
- Windows release build 成功
- Android 构建成功
- iOS 代码保持兼容
- Windows 与 Android 均使用本地 SQLite 持久化
- Windows 与 Android 复用同一套业务逻辑和数据模型
- MVP 不做设备间数据同步

### 支出
- 新增支出
- 金额校验
- 默认当前时间
- 可选择过去时间
- 禁止未来时间
- 编辑支出
- 删除支出 + 二次确认

### 分类
- 一级分类
- 二级分类
- 默认分类初始化
- 全局名称唯一
- 改名
- 停用/恢复
- 二级分类移动父级
- 固定排序，新建项追加末尾

### 周期与预算
- 自定义生活费周期，当前起始日为每月 25 日
- 周期按发钱月份命名
- 默认月预算
- 每周期预算快照
- 每周期可独立修改预算
- 历史周期不可被默认预算修改

### 查询
- 默认按当前生活费周期查看
- 支持自定义起止日期

### 统计
- 完整周期预算卡片
- 一级分类环形图
- 一级分类展开查看二级分类金额
- 每日消费趋势图
- 自定义范围不显示预算

### 导出
- CSV 导出

## MVP 不做

- 收支混合账本
- 账户体系
- 银行卡/微信/支付宝区分
- 转账
- 退款
- 负债/资产
- 登录
- 后端
- 多端数据同步（Windows 与手机数据在 MVP 中相互独立）
- 多币种
- 云备份
- 完整备份恢复
- CSV 导入
- 系统通知
- 预算阈值提醒
- 分类拖拽排序
- 商家
- 地点
- 消费事件
- 备注
- 图片/小票
- AI 分析

## 特别说明：生活费发放日后续修改

MVP 必须支持“当前周期起始日为 25 日”的自定义周期模型。

为了避免尚未确认的过渡周期预算规则影响第一版，**MVP 不要求在已经产生历史周期后提供‘修改周期起始日’的完整交互**。

未来实现该能力时必须遵守：
- 历史周期绝不修改
- 新规则从上一历史周期结束后的下一天衔接
- 允许出现长短不同的过渡周期
- 不允许日期重叠或日期空档

过渡周期预算如何确定属于 V2 设计问题，不在 MVP 中实现。
